# 핵심 코드 발췌 기준

## 사용 조건

문제 해결의 핵심이 호출 순서, 분기, 트랜잭션 경계, 동시성 제어처럼 코드의 흐름에 있을 때만 코드 블록을 추가한다. 문장이나 한 줄의 인라인 코드로 충분하면 코드 블록을 만들지 않는다.

다음과 같은 로직은 코드로 보여줄 가치가 있다.

- 캐시 hit, miss, 장애 폴백의 분기
- 락 획득, 조건부 갱신, 재시도 순서
- 트랜잭션 커밋 전후의 작업 분리
- 외부 호출 실패 뒤 보상과 상태 전이
- 커서 조건과 정렬 방향
- 동시성 제한과 작업 합류

## 발췌 방법

1. 해당 버전의 실제 저장소 파일을 연다.
2. 문제 해결에 직접 참여하는 메서드, 쿼리, 설정만 고른다.
3. 호출 순서가 여러 파일에 걸치면 독자가 따라갈 수 있는 순서로 최대한 적은 코드 블록을 배치한다.
4. 코드 블록 앞에 파일 링크와 이 코드가 보여주는 판단을 한 문장으로 적는다.
5. 코드 블록 뒤에는 줄별 해설 대신 이 코드가 지키는 조건이나 이전 버전과 달라진 점만 적는다.

가능하면 실제 코드의 연속된 구간을 사용한다. 중간을 생략해야 한다면 제어 흐름을 오해하게 만들지 않는 범위에서만 줄이고, 클래스·메서드·변수 이름은 바꾸지 않는다. 코드 조각이 독립적으로 컴파일되는 것처럼 설명하지 않는다.

## 제외 대상

다음 코드는 문제 자체와 관련이 없으면 넣지 않는다.

- 로그 출력
- 메트릭, 트레이싱, 모니터링 계측
- package와 import
- 생성자 주입과 단순 필드 선언
- getter, setter, DTO 변환 보일러플레이트
- 사용하지 않는 어노테이션과 설정
- 예외 메시지, 주석, 테스트 fixture의 부가 데이터

`@Transactional`, 락 모드, 재시도 설정처럼 문제 해결의 경계를 결정하는 어노테이션은 남긴다. 예외 처리도 실패 결과나 보상 흐름을 결정할 때는 남긴다.

## 분량

코드 블록 하나에는 하나의 시퀀스만 담는다. 전체 클래스나 파일을 복사하지 않는다. 설명보다 코드가 길어지면 핵심 분기와 상태 변화가 남을 때까지 다시 줄인다.

같은 코드를 사례 README와 버전 README에 중복해서 넣지 않는다. 사례 README에는 전체 개선 흐름을 이해하는 데 필요한 코드만 두고, 세부 구현은 해당 버전 README에서 보여준다.
