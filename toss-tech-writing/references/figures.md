# 그림 기준

## 1. 그림이 필요한 자리와 종류

토스 글은 1천 자당 엔지니어링 약 1장, 디자인 약 2장의 그림을 넣는다. **한 글 안에서 그림 종류를 섞는다.** 같은 구도의 도식이 3장 이상이면 보고서처럼 보인다.

| 자리 | 엔지니어링에서 흔한 그림 | 디자인에서 흔한 그림 |
|---|---|---|
| 구조·흐름 설명 | 단순 도식(`plain-diagram.svg`), 단계 흐름(`flow.svg`) | 사용자 여정 도식 |
| 전후 비교 | 좌우 비교 도식(`compare.svg`), 코드 Before/After, 표 | **휴대폰 화면 나란히**(`phone-compare.svg`), Don't/Do 배지 |
| 판단·분기 | 갈래가 있는 흐름도(조건을 화살표에 적는다) | |
| 결과 숫자 | 막대·선 차트(`bar-chart.svg`), 표 | 핵심 결과 한 장만 차트 |
| 실제 근거 | 대시보드·터미널·코드·알림 캡처 | 실제 앱 화면, 현장 사진 |
| 사람의 말 | 사내 대화를 다시 그린 채팅 화면 | **아바타 + 말풍선**(`quote-bubbles.svg`) |
| 모션 | | 동영상, GIF |

- **실물 캡처가 근거인 자리는 도식으로 대신 그리지 않는다.** 캡처가 없으면 `![캡처: 무엇을 어떻게 보여 줄지](TODO)`로 자리를 남긴다.
- 디자인 글에서 숫자 카드와 막대 차트는 핵심 결과 한 장에만 쓴다. 나머지는 화면과 사람의 말이다.
- 디자인 글에서 화면을 직접 그릴 때는 와이어프레임 수준으로 그리고, 실제 캡처 자리를 함께 남기지 않는다(같은 그림이 두 번 나오지 않게 하나만 고른다).

**그림은 본문에 없는 정보를 하나 이상 더해야 한다.** 그림마다 "글만 읽어서는 알 수 없는 것"을 한 줄로 적어 보고, 답이 없으면 그림을 뺀다.
- 숫자 두 개 비교(4만 → 2.6만)는 문장으로 충분하다. 차트는 추이, 여러 항목 비교, 구간 구성처럼 문장으로 읽기 어려운 것에 쓴다.
- 인용 블록으로 쓴 말을 말풍선 그림으로 또 그리지 않는다. 둘 중 하나만.
- 그림 하나에는 개념 하나. 글 전체를 한 그림에 담지 않는다.
- 구조나 값의 비교를 보여 줄 때는 순서도로 바꾸지 않는다. 순서도는 판단 분기가 핵심일 때만.
- 한 글에서 같은 바탕·카드 틀을 두 장 넘게 쓰지 않는다.

## 2. 토스 도식의 시각 규칙

토스 그림은 연도와 팀에 따라 모양이 다르다. 공통점만 지킨다.

**공통**
- 바탕은 흰색이나 아주 연한 회색(#F2F4F6, #F9FAFB). 모서리가 둥근 박스(12~18px).
- 글꼴은 Pretendard 또는 Toss Product Sans 계열 산세리프. 그림 안 가장 작은 글자도 너무 작지 않게(본문 크기 이상).
- 그림 안 글자는 짧게. 박스 하나에 굵은 이름표 한 줄, 필요하면 회색 보충 한 줄. 그림 하나에 30어절 이내.
- 강조색은 토스 파랑 하나(#3182F6). 나머지는 회색 계열(#F2F4F6, #E5E8EB, #B0B8C1, #8B95A1, #4E5968, #191F28).
- 색에 의미를 고정한다: 파랑=주인공·바꾼 것, 회색=그 밖, 빨강(#F04452, 면 #FFEEEE)=오류·문제, 초록(#03B26C, 면 #E5F8EF)=정상·해결. 문제/해결 대비가 필요할 때만 빨강·초록(또는 주황 #FE9800)을 쓴다.
- 아이콘은 거의 쓰지 않는다. 번호 원(파란 원 + 흰 숫자), ✓/✗ 정도.
- 화살표는 회색 가는 선. 분기 화살표에는 조건("승인됨", "30초 초과")을 적는다.

**그림 안 제목과 결론 띠는 선택**이다. 기본값은 **제목 없음**이다.
- 비교 패널의 이름표("공용 풀", "카드사별 풀", "AS-IS", "TO-BE")만 둔다.
- 측정 조건 같은 각주는 그림에 넣지 않고 본문이나 캡션으로 옮긴다.
- 표시(점선, 화살표, 배지)는 실제 값의 위치에만 놓는다. 구간 막대는 모든 구간에 값을 적는다.
- 그림 속 비율이나 차이는 본문이 주장하는 값과 같아야 한다. 화면 그림의 버튼 순서와 색이 본문 설명과 맞는지 확인한다.
- 대부분의 그림은 제목이 없거나 짧은 이름표("공용 풀 vs 카드사별 풀", "진입 타임라인")만 둔다.
- 결론 문장 제목 + 회색 부제 + 아래 연파랑 결론 띠를 모두 갖춘 "카드형 도식"(`compare.svg`, `flow.svg` 기본형)은 **한 글에 한 장까지**만 쓴다. 글의 핵심 깨달음을 담은 그림에만 쓴다.
- 그림 제목은 바로 위 소제목과 다른 말로 쓴다. 본문 문장을 그림에 그대로 옮기지 않는다.
- 그림 안 문장의 어미는 본문과 맞춘다(디자인 해요체, 엔지니어링은 합쇼체나 명사형).

**차트**
- 색은 파랑(주인공)과 회색(비교 대상) 두 가지. 강조할 막대 하나만 파랑으로 하는 것도 좋다.
- 값을 막대 위에 직접 쓴다. 증감은 파란 작은 글씨("+27.0p") 또는 알약 배지("▼ 약 23% 감소").
- **단위가 다른 값(초와 %)을 한 차트에 섞지 않는다.** 같은 단위끼리 같은 축, 높이는 값에 비례하게.
- 격자선은 아주 연하게, 범례는 막대 이름을 직접 붙일 수 있으면 생략한다.
- 측정 조건과 기간을 오른쪽 아래 작은 글씨로.

**예전 스타일도 토스답다**: 2022~2024년 엔지니어링 글에는 Excalidraw 손그림(연파랑 면, 손글씨체)과 draw.io 도식이 많다. 팀 기술 글이라면 이런 단순한 도식도 충분하다.

## 3. 본문과 그림을 잇는 법

- 그림 앞에서 그림을 소개하는 문장("아래 그림처럼", "한 장으로 정리하면 이런 그림입니다")은 **한 글에 한두 번**이면 충분하다. 나머지 그림은 앞 문단의 이야기에 자연스럽게 붙인다.
- 그림 뒤에서 그림을 처음부터 다시 읽어 주지 않는다. 그림에서 놓치기 쉬운 한 곳(가로축의 뜻, 세 번째 단계)만 짚거나 바로 다음 판단으로 넘어간다.
- 캡션은 선택. 넣을 때는 짧은 명사구("Node Ready와 GPU Ready의 판단 기준 비교")나 "관찰 → 조치" 형식. 외부 그림은 "출처:", 가상 데이터나 AI 생성 이미지는 그렇다고 밝힌다.
- 마크다운의 alt 텍스트는 짧은 이름표로 쓴다. 결론 문장을 alt에 넣지 않는다.

## 4. 초안의 그림 표기법

```
![카드사별 풀 구조](figures/02-pool.png)
```

그릴 수 없는 그림(캡처, 사진)은 무엇을 넣을지 적는다.

```
![캡처: 장애 당시 Grafana 대시보드. 19:02에 에러율이 4.8%로 튀는 구간에 빨간 박스](TODO)
```

캡션이 필요하면 그림 바로 다음 줄에 `*캡션 문장*`으로 쓴다.

## 5. 그림과 본문 대조 (그린 뒤 반드시)

그림을 다 그린 뒤 본문에서 그림을 가리키거나 같은 내용을 말하는 문장을 하나씩 찾아 대조한다.
- 값: 본문의 숫자와 그림의 숫자가 같은가. 합계가 맞는가. 본문이 "가장 큰 구간"이라고 한 것이 그림에서도 가장 큰가.
- 크기와 비율: 본문이 "트래픽 비중에 따라 다르게"라고 했다면 그림의 크기도 달라야 한다.
- 갈래: 본문에 나온 모든 경우(성공, 실패, 재시도, 거절, 예외 규칙)가 흐름도에 있는가.
- 시점: 그림의 값이 어느 시점에 잰 값인지 본문과 맞는가.
- 적용 범위: 그림이 일부에만 적용되는 것을 전체처럼 그리지 않았는가.
- 해결책을 아직 소개하지 않은 섹션에 해결 후 화면을 미리 보여 주지 않는가.
- 본문이 "화면이 ~하게 보였다"고 말하면 그 자리는 캡처(또는 캡처 자리 표시)가 가장 강한 근거다.

## 6. SVG를 그리는 순서

1. 그림 목록을 먼저 정한다. 종류가 겹치지 않는지, 카드형 도식이 한 장 이하인지 확인한다.
2. `assets/figures/`에서 가까운 템플릿을 복사한다.
   - `plain-diagram.svg`: 틀 없는 단순 도식(기본값)
   - `compare.svg`: 카드형 좌우 비교(한 글에 한 장, 제목·띠는 지워도 된다)
   - `flow.svg`: 카드형 단계 흐름(제목·띠는 지워도 된다)
   - `bar-chart.svg`: 막대 차트
   - `phone-compare.svg`: 디자인 글의 화면 비교(라벨 AS-IS / TO-BE, 그림 안 해설 문구 없음). 실제 캡처가 있으면 캡처를 쓰고 이 그림은 만들지 않는다.
   - `quote-bubbles.svg`: 사용자·동료의 말
3. 박스 수와 문구를 바꾸고 좌표를 맞춘다. 한 줄 20자 안팎으로 끊는다.
4. `scripts/render_svg.sh 그림.svg`로 PNG를 만들고 **Read로 열어 눈으로 확인**한다: 글자 넘침, 겹침, 남는 빈 공간, 차트 높이가 값에 비례하는지, 분기가 빠지지 않았는지.
5. 본문의 `![...](...)`가 PNG를 가리키게 한다.
