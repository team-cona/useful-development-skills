# 재료: 이상거래 탐지(FDS) 오탐 줄이기 (분야: 엔지니어링 / AI·ML)
글쓴이: 토스뱅크 FDS팀 ML Engineer 김도윤

- 토스뱅크 이체 FDS: 이체 요청마다 모델이 위험 점수(0~1)를 매기고 0.8 이상이면 이체를 잠시 보류 + 본인 확인(ARS) 요구.
- 문제: 보류된 이체 중 실제 사기는 약 3%. 나머지 97%는 정상 고객. 하루 보류 약 1,900건. 상담센터 FDS 관련 문의가 전체 문의의 11%.
- 고객 VOC 원문: "월세 보내는데 왜 매달 막혀요?", "내 돈 내가 보내는데 범죄자 취급받는 기분이에요"
- 처음 접근: 모델 성능(AUC) 올리기. 피처 40개 추가, 모델 GBDT → 더 큰 앙상블. AUC 0.962 → 0.968. 그런데 보류 건수는 거의 그대로(-2%).
- 오탐 사례 300건 직접 라벨링해서 분류해봄: 58%가 "매달 같은 사람에게 비슷한 금액을 보내는 반복 이체"(월세, 용돈, 회비). 모델은 '처음 보는 수취인 + 큰 금액'에 강하게 반응하는데, 반복 이체도 첫 달 패턴이 리셋되는 경우(수취 계좌 변경, 3개월 이상 공백)가 많았음.
- 팀 내 논쟁: "반복 이체 화이트리스트 만들자" vs "사기범이 반복 이체를 흉내 내면 뚫린다". 결국 화이트리스트 대신 '관계 피처'로 가기로.
- 해결: 송금인-수취인 관계 그래프에서 관계 점수 계산(과거 이체 횟수, 주기성, 금액 변동성, 양방향 이체 여부). 모델 입력에 추가 + 임계값을 관계 점수 구간별로 다르게(관계 강하면 0.92, 약하면 0.8 유지).
- 오프라인 검증: 최근 6개월 로그 재생. 사기 탐지율(재현율) 91.2% → 90.8% (-0.4%p), 보류 건수 -41%.
- 사기 탐지율이 조금이라도 떨어지는 걸 리스크팀이 우려 → 2주간 섀도 모드(실제 보류는 기존 모델, 새 모델은 판단만 기록)로 운영 후 비교. 섀도 기간 동안 새 모델이 놓친 사기 2건, 둘 다 '오래된 관계 계정이 탈취된' 케이스.
- 보완: 관계 점수가 높아도 '기기 변경 + 24시간 내 첫 이체'면 관계 점수 무시 규칙 추가. 이후 재현율 91.3%로 기존과 동등.
- 정식 적용 후 4주: 하루 보류 1,900건 → 1,050건(-45%), FDS 관련 상담 문의 비중 11% → 6%. 보류 건 중 실제 사기 비율 3% → 5.6%.
- 쓰는 도구: 피처 저장소는 사내 Feast 기반, 그래프 집계는 Spark 배치(일 1회) + 당일 증분은 Flink. 모델 서빙은 사내 서빙 플랫폼(p99 18ms 제약).
- 한계: 관계 점수가 일 배치라 당일 처음 생긴 관계는 반영 늦음. 가족 간 계좌 공유처럼 '관계'가 애매한 경우 여전히 오탐.
- 배운 점: 모델 점수를 올리는 것보다, 오탐을 직접 열어보는 게 먼저였다.
