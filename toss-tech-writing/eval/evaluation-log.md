# 평가와 개선 기록

이 스킬을 만들고 고친 과정과 결과다. 다음에 스킬을 고칠 때 같은 실수를 반복하지 않도록 남긴다.

## 분석 자료

- toss.tech 글 395편 수집(사내 API `api-public.toss.im/api-public/v3/ipd-thor/api/v1/workspaces/15/posts` + 글 페이지 HTML). 본문이 있는 글 307편, 2024년 이후 227편을 기준으로 삼았다.
- 정량 분석: `eval/scripts/stats.py`, 기준 분포는 `scripts/baseline.json`.
- 정성 분석: 대표 글 55편을 5개 묶음으로 나눠 그림까지 직접 보며 분석.
- 재수집: `eval/scripts/scrape.py <작업폴더>` (작업폴더/api/list_*.json에 목록 API 응답을 먼저 받아 둔다).

## 평가 방법

1. **style_check 정량 점수**: 실제 토스 글 중앙값 79(엔지니어링)·81(디자인).
2. **기준표 채점**(references/rubric.md, 50점): 실제 토스 글 2편을 먼저 읽은 독립 평가자.
3. **단락 블라인드**(`eval/scripts/blind.py`): 실제 단락 3개 + 생성 단락 1개, 우연 25%.
4. **짝 비교**(`eval/scripts/paired.py`): 실제 글에서 사실만 뽑은 메모로 다시 쓰고 원문과 나란히 비교, 우연 50%. 내용이 같아 문체만 비교된다. 가장 공정한 시험.

## 배운 점

1. **장치를 전부 넣으면 오히려 들킨다.** 토스다운 장치는 몇 개만, 불규칙하게.
2. **분석가 몇 명의 인상보다 전체 데이터가 맞다.** "소제목은 문장형"(인상) → 실제로는 명사구 63%. "한 문장 문단은 전환점"(인상) → 실제로는 문단의 절반이 평범한 한 문장. 규칙을 만들기 전에 227편으로 확인한다.
3. **평가 방법의 결함을 먼저 의심한다.** 시나리오 재료의 익명성(“A 카드사”), 부제·글쓴이 줄 노출, 변환기가 만든 "1. 1. 1." 번호가 판별 근거가 됐었다.
4. **짝 비교의 마지막 벽은 사람 원고의 흔적이다.** 오타, 붙은 따옴표, 남은 자리 표시 같은 것들. 이것은 흉내 내지 않는다. 대신 재료에 없는 해석·정리 문장을 만들지 않고, 재료의 감정과 장황함을 줄이지 않는 쪽으로 다가간다.
5. **한 번에 들킨 이유를 데이터로 바꾼다.** 평가자 지적은 반드시 227편 분포로 확인한 뒤 규칙으로 만든다(평가자도 몇 편만 보고 틀린 일반화를 한다).

## 다음에 해볼 것

- 짝 비교를 더 많은 글(10편 이상)로 늘려 확신도 변화를 통계적으로 본다.
- 평가자에게 원문 없이 생성 글만 주고 "토스 글인가"를 묻는 단독 판별도 함께 본다.
- 그림 평가를 따로 떼어, 실제 토스 그림과 생성 그림을 나란히 놓고 판별하게 한다.
